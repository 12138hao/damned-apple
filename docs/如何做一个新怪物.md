# 从零做一个新怪物：以 HopApple 为例

> 这份文档把「跳跃苹果怪」的完整制作过程拆成可复用的步骤。
> 以后你要做第二只、第三只怪，照着这个流程走即可。

---

## 0. 先说名字

**`hopapple` = hop（蹦）+ apple（苹果）**

- `apple`：它的本体就是第一关那只苹果怪（`AppleEnemy`）的同一套美术风格
- `hop`：它和第一关苹果怪最本质的区别——**它不会走，只会一下一下地蹦**

第一关的苹果怪叫 `AppleEnemy`，是靠 `Enemy` 基类的默认巡逻逻辑「走」过来的；
这只改成蹦着走，所以类名叫 `HopAppleEnemy`，场景节点名 `hopapple`。

命名逻辑是「**行为 + 本体**」：光叫 `Apple2` 你三个月后就分不清它和第一关有什么区别了。

---

## 1. 整体流程

```
① 素材     三视图立绘 → 抠背景 → 拼 32 帧精灵表
② 场景     CharacterBody2D + 5 个子节点（基类硬取 4 个）
③ 脚本     继承 Enemy，覆写 6 个虚方法，写一个 5 态状态机
④ 调参     全部走 [Export]，在检查器里改，不改代码
```

## 2. 素材：从三张立绘到 32 帧精灵表

### 2.1 为什么要「三视图」

一张图只能做一个姿态。要做出「朝左走」「朝右走」「正面咬人」三种观感，
至少需要三张：**朝左、朝右、正面张嘴**。

引擎只有 `Sprite2D` + `hframes`，一帧就是一格，所以要把这些姿态**拼成一张长条图**。

### 2.2 抠背景（`tools/applemon/prep_sprites.py`）

**做法**：从图片**四条边**开始做泛滥填充（flood fill），把连通的背景色变透明。

**为什么不能直接「全图删白色/删背景色」**：
苹果的牙齿、高光也是白的，全图删会把它们一起吃掉。但它们的**位置被红色包住、和外面不连通**，
所以从四边泛滥填充不会碰到它们——这是关键区别。

**这一步踩过的两个坑**：

| 坑 | 现象 | 正解 |
|---|---|---|
| 白底容差开太大 | 整排上槽牙没了 | 背景是纯 `(255,255,255)`，牙齿是 `(244,237,245)`，**只差 19** → 容差必须 < 19，最终用 **4** |
| 「边缘柔化」 | 贴着背景的牙齿被做成半透明 | 直接关掉。这套美术本身有深色描边，硬边更干净 |

**深色背景的情况**（蹲下立绘）：背景 `(42,46,58)`、海军蓝衣服 `(34,42,68)`，**只差 10** → 容差只能给 **6**。

最后再补一刀「**只保留最大连通块**」，把边角散落的噪点一次清掉。

### 2.3 拼帧（`tools/applemon/make_sheet.py`）

32 帧的分配不是随便切的，要**按状态分段**，因为脚本靠帧号索引：

| 帧段 | 帧数 | 内容 | 为什么 |
|---|---|---|---|
| 0–3 | 4 | 呼吸（朝右） | 站立时用 |
| 4–7 | 4 | 呼吸（朝左） | |
| 8–12 | 5 | 蹦跳（朝右） | 蹲 → 起跳 → 顶点 → 下落 → 落地 |
| 13–17 | 5 | 蹦跳（朝左） | 左右各一套，不靠镜像 |
| 18–21 | 4 | 飞扑（朝右） | 往哪扑用哪边 |
| 22–25 | 4 | 飞扑（朝左） | |
| 26–31 | 6 | 死亡炸开 | 三张碎裂图 + 交叉溶解 |

**为什么左右各做一套而不是用 `FlipH` 镜像**：
这套美术是手绘的三视图，左右两张的光影和五官位置并不完全对称；
镜像会让人一眼看出来「翻面了」。所以宁可多花 8 帧。

### 2.4 从静态图到「动起来」

每一帧都是对静态图做**几何变换**（缩放、压扁拉伸、位移、分块），没有重新绘制。

- **蹦跳**：蹲（压扁 `sy=0.88`）→ 起跳（拉长 `sy=1.13`）→ 顶点（`1.02`）→ 下落 → 落地压扁（`0.85`）
- **飞扑**：蓄力后仰 → 压紧 → 前冲拉长（`sx=1.32`）→ 回收
- **死亡**：三张碎裂图之间插**交叉溶解**帧，让过程连起来

> ⚠️ 缩放的坑：第一版按「高度等比缩放」，结果整个人变小了，不像蹲下。
> **正确做法是横纵分开**：宽度对齐站立帧、只压高度。

## 3. 场景：节点怎么搭

### 3.1 节点树

```
hopapple (CharacterBody2D)   ← collision_layer = 4（敌人层），挂 HopAppleEnemy.cs
├─ CollisionShape2D           ← 本体碰撞，矩形 54×68，position (0,11)
├─ Sprite2D                   ← 贴图 hop_apple_sheet.png，hframes = 32，scale 0.65
├─ HpBar (TextureProgressBar) ← 血条（可选）
├─ RayLeft  (RayCast2D)       ← 探脚下有没有地
├─ RayRight (RayCast2D)
└─ HurtArea (Area2D)          ← collision_mask = 2（玩家层）
   └─ CollisionShape2D        ← 矩形 64×73，position (0,11)
```

### 3.2 基类会硬取 4 个节点，缺一个就崩

`Enemy._Ready()` 里是这样写的：

```csharp
_sprite   = GetNode<Sprite2D>("Sprite2D");       // 名字必须精确
_rayLeft  = GetNode<RayCast2D>("RayLeft");
_rayRight = GetNode<RayCast2D>("RayRight");
_hurtArea = GetNode<Area2D>("HurtArea");
_bar      = GetNodeOrNull<TextureProgressBar>("HpBar");   // 这个可选
```

**是 `GetNode` 不是 `GetNodeOrNull`** —— 少一个节点直接抛异常，怪物完全不跑。
我第一次跑就崩在这，报错指向 `Enemy.cs:81`。

### 3.3 碰撞体尺寸怎么算

**坑：本体碰撞体要和贴图脚底对齐。**

精灵表格子 160×160，内容画在 `y=20~150`（脚底 150），节点原点在格子中心 80：

```
内容脚底相对节点 = 150 - 80 = +70（贴图坐标）
乘 Sprite 的 scale 0.65  →  +45.5（世界坐标）
碰撞体高 68，半高 34 → 中心 y = 45.5 - 34 = +11
```

这样碰撞体的底边正好落在地面线上，不会浮空也不会陷进去。

**坑：受击区（HurtArea）必须 ≥ 本体碰撞体。**

这是「碰到了却不扣血」的根因——玩家的 `mask` 含敌人层，会被**身体挡住**，
贴上去时中心距离固定 43px、玩家边缘离怪物中心 27px。
如果 HurtArea 是半径 30 的圆：

- 水平只重叠 **3px**，稍微偏一点就漏
- 垂直只覆盖 ±30，而怪物高 68 → **从上方/下方贴上来完全检测不到**

所以受击区用**矩形 64×73**（比身体 54×68 各边大 5px），任何身体接触都必然重叠。

## 4. 脚本：继承 + 状态机

### 4.1 继承关系

```csharp
public partial class HopAppleEnemy : Enemy    // 不是 CharacterBody2D！
```

`Enemy` 已经写好了通用部分：重力、移动、受击无敌、击退、接触伤害、血条、死亡计时、复活。
子类只写「怎么动」「播什么帧」「死的时候做什么」。

### 4.2 六个可覆写点（都在 `Enemy.cs`）

| 方法 | 什么时候调用 | 这只怪怎么用 |
|---|---|---|
| `ComputeHorizontalVelocity(dt)` | 每物理帧，取水平速度 | 按状态返回：蹦跳速度 / 扑击速度 / 0 |
| `UpdateAnimation(dt)` | 每物理帧，选帧 | 按状态切换帧段（见下表） |
| `OnDeath()` | 死亡瞬间 | 立刻关碰撞 + 跳到死亡首帧 |
| `UpdateDead(dt)` | 死亡期间 | 只倒计时，不压扁不淡出 |
| `OnDeadFinished()` | 死亡动画播完 | 没覆盖（用基类的隐藏逻辑） |
| `Respawn()` | 玩家复活时 | 重置状态机 |

### 4.3 状态机

```csharp
private enum St { Idle, Hop, Charge, Lunge, Recover }
```

```
Idle ──(发现玩家)──→ Charge ──(蓄力够了)──→ Lunge ──(落地/超时)──→ Recover ──→ Idle
  └──(计时到)──→ Hop ──(落地)──→ Idle
```

**为什么要有 `Charge`（蓄力）**：给玩家反应时间。没有这一段的扑击是「不讲道理」的，
玩家会觉得被偷袭。这只怪给了 0.5 秒。

**为什么要有 `Recover`（喘气）**：扑完不设防，玩家有反击窗口。这也是难度平衡的一部分。

### 4.4 动画：按状态选帧，不要循环播

```csharp
case St.Hop:
    if (Velocity.Y < -220f)      _sprite.Frame = start + 1;   // 刚起跳：拉长
    else if (Velocity.Y < 0f)    _sprite.Frame = start + 2;   // 接近顶点
    else                         _sprite.Frame = start + 3;   // 下落
```

**关键**：蹦跳帧按**物理状态**选，不是 5 帧循环播放。
循环播放的话，高速下看起来像「在扑腾翅膀」，而按物理状态走才像「跳」。

### 4.5 判定：为什么要「扫掠」而不是「圆」

普通的重叠判定（圆/矩形）在高速下会**穿透**：1037 px/s 时每物理帧走 17px，
可能直接从玩家身上跨过去，两次采样都没检测到。

所以用**扫掠线段**：把「上一帧位置 → 本帧位置」连成线，算玩家到线段的最近距离。

```csharp
Vector2 ab = b - a;                                  // 这一帧走过的线段
float t = Clamp((c - a).Dot(ab) / ab.LengthSquared(), 0f, 1f);
Vector2 closest = a + ab * t;                        // 线段上离玩家最近的点
```

**还有一个更隐蔽的坑：判定的 Y 基准不能用「当前高度」。**

飞扑是抛物线，最高抬升 34px。怪物在空中时碰撞体占 `391~459`，玩家占 `461~493`
—— 差 2px，怪物是**擦着玩家头顶飞过去**的。用当前高度算，顶点时 `dy=52 > 判定半高 50`，
整段飞扑一次都判不中。

正解：用 **`_lungeY`（起跳瞬间的高度）** 做水平扫掠。站着不动时 `dy` 恒为 18，
不随弧线漂移；玩家跳起来仍然躲得掉。

> **通用原则：判定框的参考高度必须是稳定锚点（起跳点 / 地面），不能用会随动画起伏的当前值。**

## 5. 调参：一切走 Export

### 5.1 不要暴露「中间量」

我最初暴露的是「向上初速度」（`LungeJumpImpulse`），
但高度和它是**平方关系**（`h = v²/2g`），你每次想调高度都得让我算。

改成暴露 **`LungeHeight`（像素）**，内部自动换算：

```csharp
float jumpImpulse = Mathf.Sqrt(2f * Gravity * LungeHeight);
float air = 2f * jumpImpulse / Gravity;
```

同理，距离用 **`LungeDistanceScale`（倍率）**，1.0 = 正好落在玩家身上，1.5 = 冲过头。

**原则：参数名要让人能直接想象出画面，而不是一个数学中间值。**

### 5.2 常用参数速查

| 参数组 | 参数 | 作用 |
|---|---|---|
| 蹦跳 | `HopInterval` / `HopSpeed` / `HopHeight` | 跳的节奏、距离、高度 |
| 侦测 | `DetectRangeX` / `DetectRangeY` | 多近能发现玩家 |
| 飞扑 | `LungeChargeTime` | **反应窗口，最直接的难度旋钮** |
| | `LungeHeight` / `LungeDistanceScale` | 弧线高度、落点距离 |
| | `LungeMinSpeed` / `LungeSpeed` | 速度上下限 |
| 判定 | `LungeHitWidth/Height/CenterY` | 命中框（贴着体积） |

## 6. 验证：没有画面时怎么测

Godot 的 `--headless` 能跑逻辑但没有渲染，也没有键盘输入。三个常用手法：

**① 时间戳量时长**

```csharp
GD.Print($"[T] {Time.GetTicksMsec()} 蓄力开始");
```

跑完看两行的时间差，就知道蓄力是 494ms 还是 10000ms。

**② 临时改判断条件**

蹲下依赖按键，headless 测不了。做法是把 `Input.IsActionPressed("crouch")`
临时换成 `true`，跑完用 `cp` 备份还原。

**③ 只打印关心的帧**

```csharp
if (_ar.GetOverlappingBodies().Count > 0) GD.Print($"重叠 HP={_player.Hp}");
```

比每 30 帧采样强得多——之前就是采样刚好避开了所有重叠帧，误判成「检测失效」。

## 7. 复刻清单（Checklist）

做一个新怪，按顺序打勾：

- [ ] 三视图立绘准备好（朝左 / 朝右 / 正面）
- [ ] 抠背景：先 `ffmpeg -i` 看真实格式，再量背景色和角色色的差值决定容差
- [ ] 关掉「边缘柔化」，加「只保留最大连通块」
- [ ] 按状态切分帧段，左右各一套（不用镜像）
- [ ] `CharacterBody2D` + **5 个子节点**（Sprite2D / RayLeft / RayRight / HurtArea / HpBar）
- [ ] `collision_layer = 4`，`HurtArea.collision_mask = 2`
- [ ] 受击区 ≥ 本体碰撞体
- [ ] 碰撞体底边对齐贴图脚底
- [ ] 继承 `Enemy`，覆写 `ComputeHorizontalVelocity` + `UpdateAnimation`
- [ ] 死亡时立刻关碰撞（不要等动画播完）
- [ ] 判定用扫掠 + 稳定锚点
- [ ] 所有参数 `[Export]`，名字用物理量（高度/倍率）
- [ ] `dotnet build` 确认「**0 个错误**」
- [ ] 无头跑一遍，用日志验证状态流转

## 8. 踩坑速查

| 现象 | 原因 | 解法 |
|---|---|---|
| 怪物完全不跑、报 NullReference | 缺 RayLeft/RayRight/HurtArea | 补节点，名字要精确 |
| 牙齿/眼睛被抠掉 | 抠图容差太大 | 量出背景和牙齿的差值，容差要小于它 |
| 碰到不扣血 | 受击区 < 本体碰撞体 | 受击区做成矩形且更大 |
| 飞扑撞上不疼 | 判定 Y 用了当前高度 | 改用起跳高度做扫掠 |
| 没碰到也扣血 | 判定框开太大 | 收回「刚好贴上」的尺寸（怪半宽+人半宽） |
| 蹲下像「变小」 | 等比缩放 | 横纵分开：宽度不变、只压高度 |
| 改完没反应 | 构建失败了，跑的是旧程序 | 必须确认「0 个错误」 |
