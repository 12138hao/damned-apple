### 1.2 模块分解

| # | 功能 | 行号 | 关键机制 |
|---|---|---|---|
| 1 | 初始化 | 201 | 读 `GameState` 的血量/武器/载具，绑定 HUD |
| 2 | 左右移动 | `_PhysicsProcess` | `MoveToward` 加/减速，不是瞬间变速 |
| 3 | 跳跃三件套 | — | **土狼时间**（出平台后仍可跳）+ **跳跃缓冲**（落地前按也算）+ **松手切跳跃**（按住跳更高） |
| 4 | **单向平台** | 546-559 | 按下 `S` 时把平台层从 `collision_mask` 摘掉，`_physics` 结束后恢复 |
| 5 | **鼠标瞄准** | 559-588 | `GetGlobalMousePosition()` 求角度，`ClampAimAngle` 限制在合理的挥击范围 |
| 6 | **空手连击** | 588-640 | `ComboWindow=0.45s` 内再点算连击，`MaxCombo=4`；最后一拳 `finisher` 时伤害 ×2、击退 120 → 320 |
| 7 | **蓄力挥击** | 640-786 | 按住攒 `_chargeTime`，松手按 `ratio = _chargeTime / ChargeMaxTime` 在 `DamageMin~Max` 之间 `Lerp`；`_hitThisSwing` 保证一次挥击只打一次 |
| 8 | 武器槽 | 786 / 930 | 4 格，`FindNextWeaponSlot` 跳过空槽 |
| 9 | **载具** | 798-930 | `ToggleVehicle` 换贴图、改速度、换攻击方式（水平子弹） |
| 10 | 受击 | 311 | 无敌帧 `HurtCooldown` + 击退，击退期间不再吃伤害 |
| 11 | 死亡 / 复活 | 332-498 | 五段：`Die` → `StartRevive` → 切场景/回存档点 → `FinishRevive` |
| 12 | 存档点写入 | 370 | `SetRevivePoint(groundPos)`，会按身高把地面坐标抬到身体中心 |
| 13 | 相机锁定 | 1101-1105 | `_cam.Position.y = CameraFixedY - GlobalPosition.Y`（反向补偿，因为相机是子节点） |

### 1.3 两个容易忽略的细节

- **相机为什么用"反向补偿"**：Camera2D 是 box 的子节点，会跟着玩家动。要让它在世界里停在 `CameraFixedY`，就得在**局部坐标**里减去玩家当前 Y。这行是理解"锁定高度"的关键。
- **朝向不是一根线决定的**，分三种情况（`Box.cs:119` 注释写得很清楚：「朝向只由输入决定，不被击退带偏」）：
  - 空手走路 → 只跟**方向键**（1070）
  - 持武器 → 跟**鼠标**（883）
  - 挥击过程中 → **锁定在出招方向**（1163、670），否则鼠标一抖人物就翻面、刀和人方向相反

## 2. 敌人系统

| 文件 | 行数 | 职责 |
|---|---|---|
| `Enemy.cs` | 364 | **基类**：左右巡逻、撞墙/临边掉头、受击、击退、死亡、血条 |
| `AppleEnemy.cs` | 193 | 会追踪玩家的苹果怪（继承 Enemy） |
| `SlimeEnemy` / `Enemy2` / `Enemy3` | 17~22 | 极简子类，只改贴图帧段或参数 |
| `DeathDrop.cs` | 55 | 挂在敌人下面：死时生成掉落物 |
| `DeathExplosion.cs` | 110 | 挂在敌人下面：死时范围伤害，可选留毒圈 |
| `EnemyManager.cs` | 66 | 玩家复活时把场上所有怪重置回初始位置与血量 |

**设计模式要点**：`Enemy` 是模板方法模式——基类写好巡逻循环，子类只覆盖"怎么动"和"贴图帧段"。这样加新怪只要写十几行。

**`EnemyManager` 解决的坑**：玩家死了，怪却停在被打残的状态，复活一看满地图残血怪。它记住每只怪的初始状态，复活时统一还原。

## 3. Boss 战

| 文件 | 行数 | 职责 |
|---|---|---|
| `BossEnemy.cs` | 559 | 站桩 Boss。**两套状态机要分清**：血量阶段（`PhaseChangeHpPercent=50`，血量到 50% 换贴图、解锁喷毒）和行为状态机（`enum Phase { Idle, Airborne, SpitCharge, Spitting }`，管"当前在干什么"） |
| `BossArena.cs` | 513 | 战场导演：进场封锁出口、拉近镜头、显示血条、战后剧情 |
| `CollapseFloor.cs` | 98 | 可坍塌地板，平时是普通 StaticBody2D |
| `FallTrigger.cs` | 87 | 掉落触发：解除相机 Y 锁，掉到指定深度后处理 |

### 流程串联

```
玩家踏进战场边界
  → BossArena 锁门 + 拉镜头 + 显示血条
玩家打掉 Boss
  → OnBossDied (406)
  → 倒地哭泣 + 播剧情
  → _floor.Collapse()          地板开始塌
  → FallTrigger.Arm()          解除相机 Y 锁，开始监视下落
  → 玩家掉过 TriggerY          FallTrigger:68 处理去向
```

**注意**：`FallTrigger:68` 现在只是 `_player.GlobalPosition = TeleportTo`——**同场景瞬移**，不会切场景。第二关要接在这里。

## 7. 状态与存档

`GameState.cs`（154 行）是跨场景的唯一真相源，存这些：

- 血量、武器 4 格 + 当前槽、载具
- 复活点三件套：`RevivePointKey` / `ReviveScenePath` / `RevivePosition`
- 已读过哪些对话、已捡过哪些道具
- **`PrepareTravel(hp, spawn, weapons, slot, invuln)`**：切场景前打包，新场景里 `Box._Ready` 自己取

**三种存档的区别（容易混）**：

| 谁 | 何时 | 回血 | 消失 |
|---|---|---|---|
| `RevivePoint` | 玩家按 E | 会 | 会 |
| `SpawnSavePoint` | 进场景自动 | 不会 | 不会 |
| `Door` 切场景 | 对话/进门 | 不带（原样传） | — |

## 10. 武器数据（`WeaponData.cs` + `.tres`）

| 参数 | 木棒 `bat.tres` | 尺子 `ruler.tres` |
|---|---|---|
| 伤害（不蓄力→蓄满） | 20 → 40 | 30 → 60 |
| 击退 | 180 → 700 | 270 → 1050 |
| 挥击时长 | 0.22 s | 0.22 s |
| 扫过角度 | 120° | 120° |
| 起始角 | -75° | -75° |
| 距离倍率 | 1.0 | **1.5** |
| 蓄满变突刺 | 否 | **是**（`ChargeThrust`，倍率 2.0，阈值 0.95） |

改武器手感**不用碰代码**，改 `.tres` 就行——这是把数据从逻辑里拆出去的好处。
